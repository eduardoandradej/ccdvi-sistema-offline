 SISTEMA DVI OFFLINE - CCDVI/SEPOL
 RUNBOOK DE INSTALACAO E EXECUCAO - UBUNTU 24.04 LTS
===============================================================================

 Versao do runbook ....: 1.1 (15/10/2026) - inclui operacao via systemd
 Versao do sistema ....: 0.1.0 (MVP)
 Modo de execucao .....: instalacao nativa (sem conteineres), em um servidor
                         ou notebook Ubuntu, acessada pelo navegador na rede
                         local.
 Uso ..................: DEMONSTRATIVO, SOMENTE COM DADOS FICTICIOS.

 Validacao: este roteiro foi executado do inicio ao fim em Ubuntu 24.04.5 LTS,
 a partir de um clone novo do repositorio e de um banco vazio. Depois da
 instalacao, os 5 testes automatizados de navegador (login, cadastro AM e PM,
 anexos, comparacao e permissoes) foram aprovados.

 Convencoes:
   $  comando executado como usuario comum (com permissao de sudo)
   #  comentario (nao digite)
   <...> valor que voce deve escolher


-------------------------------------------------------------------------------
 0. REQUISITOS
-------------------------------------------------------------------------------

 - Ubuntu Server ou Desktop 24.04 LTS, 64 bits (x86_64).
 - Minimo sugerido: 4 nucleos, 8 GB de RAM, 20 GB livres em disco.
 - Usuario com permissao de sudo.
 - Internet DURANTE A INSTALACAO (para baixar pacotes). Depois de instalado,
   o sistema funciona somente na rede local, sem internet.
 - Portas usadas: 5173 (interface web) e 8000 (API, apenas local).

 Tempo estimado: 15 a 25 minutos.


-------------------------------------------------------------------------------
 1. ATUALIZAR O SISTEMA E INSTALAR PACOTES BASICOS
-------------------------------------------------------------------------------

 $ sudo apt update
 $ sudo apt -y upgrade
 $ sudo apt install -y git curl ca-certificates postgresql python3.12-venv

 # Conferir versoes:
 $ python3 --version          # esperado: Python 3.12.x
 $ psql --version             # esperado: psql (PostgreSQL) 16.x


-------------------------------------------------------------------------------
 2. INSTALAR O NODE.JS 22
-------------------------------------------------------------------------------

 O Node.js do repositorio padrao do Ubuntu 24.04 e antigo (versao 18). Use o
 repositorio oficial NodeSource, versao 22:

 $ curl -fsSL https://deb.nodesource.com/setup_22.x -o /tmp/nodesource_setup.sh
 $ sudo bash /tmp/nodesource_setup.sh
 $ sudo apt install -y nodejs

 # Conferir:
 $ node --version             # esperado: v22.x
 $ npm --version              # esperado: 10.x


-------------------------------------------------------------------------------
 3. INICIAR O POSTGRESQL E CRIAR O BANCO
-------------------------------------------------------------------------------

 3.1 Iniciar o servico e habilitar inicio automatico no boot:

 $ sudo systemctl enable --now postgresql
 $ sudo systemctl status postgresql --no-pager      # deve mostrar "active"

 3.2 Criar usuario e banco. ESCOLHA UMA SENHA e anote (use apenas letras,
     numeros e hifen para evitar problemas na URL de conexao):

 $ sudo -u postgres psql -c "CREATE ROLE dvi LOGIN PASSWORD '<SENHA_DO_BANCO>';"
 $ sudo -u postgres psql -c "CREATE DATABASE dvi OWNER dvi;"

 # Testar a conexao (pede a senha do banco):
 $ psql -h localhost -U dvi -d dvi -c "select 1;"
 # Deve mostrar uma tabela com o valor 1. Saia se ficar no prompt (\q).


-------------------------------------------------------------------------------
 4. BAIXAR O SISTEMA
-------------------------------------------------------------------------------

 $ cd ~
 $ git clone https://github.com/eduardoandradej/ccdvi-sistema-offline.git
 $ cd ccdvi-sistema-offline

 # Se o repositorio for privado, o git pedira usuario e um token de acesso
 # pessoal do GitHub (no lugar da senha).


-------------------------------------------------------------------------------
 5. CONFIGURAR
-------------------------------------------------------------------------------

 5.1 Criar o arquivo de configuracao a partir do modelo:

 $ cp .env.example backend/.env

 5.2 Editar o arquivo:

 $ nano backend/.env

 Ajuste estas duas linhas (remova o "#" do inicio da linha da senha do seed):

   DVI_DATABASE_URL=postgresql+psycopg://dvi:<SENHA_DO_BANCO>@localhost:5432/dvi
   DVI_SEED_PASSWORD=<SENHA_DOS_USUARIOS_DE_LABORATORIO>

   - <SENHA_DO_BANCO> e a mesma do passo 3.2.
   - <SENHA_DOS_USUARIOS_DE_LABORATORIO> deve ter NO MINIMO 10 caracteres.
     Ela sera usada por todos os usuarios ficticios de demonstracao.

 Salve com Ctrl+O, Enter, e saia com Ctrl+X.

 5.3 Proteger o arquivo (contem senhas):

 $ chmod 600 backend/.env

 5.4 Garantir que os scripts sao executaveis:

 $ chmod +x scripts/*.sh


-------------------------------------------------------------------------------
 6. INSTALAR DEPENDENCIAS E INICIAR A APLICACAO
-------------------------------------------------------------------------------

 Um unico script faz tudo: cria o ambiente Python, instala as dependencias,
 cria as tabelas no banco (migracoes), cadastra a operacao, as bases e os
 usuarios ficticios com registros de demonstracao, instala a interface e
 inicia API + interface.

 $ scripts/dev-up.sh

 Na primeira execucao leva alguns minutos (download de dependencias).
 Sinais de sucesso no terminal, nesta ordem:

   Running upgrade  -> 0001, esquema inicial
   Operacao: SIMULADO CCDVI 2026
   Usuarios de laboratorio: operador.am, operador.pm, revisor, ...
   Frontend: http://<IP>:5173  (API em 127.0.0.1:8000)
   VITE v5.4.21  ready
   Uvicorn running on http://127.0.0.1:8000

  O terminal fica "preso" mostrando os registros: isso e normal NA PRIMEIRA
  EXECUCAO. Apos validar a aplicacao, pressione Ctrl+C e configure o servico
  systemd na secao 9, para que rode em segundo plano e inicie no boot.

-------------------------------------------------------------------------------
 9. CONFIGURAR O SYSTEMD (UMA VEZ, APOS A PRIMEIRA EXECUCAO)
-------------------------------------------------------------------------------

 OBJETIVO: iniciar, parar, reiniciar e consultar o Sistema DVI sem manter
 um terminal aberto. Esta unidade controla API FastAPI e interface Vite.

 IMPORTANTE: esta configuracao foi testada no laboratorio pelo operador.
 O modo usa o script de desenvolvimento dev-up.sh; nao e implantacao final.

 9.1 Encerrar qualquer execucao manual antes de criar o servico:
     - Se scripts/dev-up.sh ainda estiver no terminal, pressione Ctrl+C.
     - Verifique se as portas 5173 e 8000 estao livres:
 $ sudo ss -ltnp | grep -E ':(5173|8000)\b' || true

     Se outra instancia estiver ocupando as portas, identifique o processo
     antes de encerra-lo. Evite comandos pkill genericos.

 9.2 Criar a unidade (caminho e usuario desta VM de laboratorio):
 $ sudo nano /etc/systemd/system/ccdvi.service

 Cole EXATAMENTE o seguinte conteudo, sem os delimitadores abaixo:

 ----- INICIO: /etc/systemd/system/ccdvi.service -----
 [Unit]
 Description=CCDVI - Sistema DVI Offline
 Wants=network-online.target
 After=network-online.target postgresql.service
 Requires=postgresql.service

 [Service]
 Type=simple
 User=suporte
 WorkingDirectory=/home/suporte/ccdvi-sistema-offline
 ExecStart=/bin/bash /home/suporte/ccdvi-sistema-offline/scripts/dev-up.sh --no-seed
 Restart=on-failure
 RestartSec=5
 KillMode=control-group
 TimeoutStopSec=20

 [Install]
 WantedBy=multi-user.target
 ----- FIM: /etc/systemd/system/ccdvi.service -----

 ATENCAO: ajuste User, WorkingDirectory e ExecStart se o repositorio estiver
 em outro diretorio ou tiver sido instalado com outro usuario. Este exemplo
 corresponde ao laboratorio ccdvi-ubuntu-lab (usuario suporte).

 O parametro --no-seed impede repetir a criacao dos dados ficticios.
 A primeira execucao SEM --no-seed precisa ter ocorrido no passo 6.

 9.3 Registrar a unidade, ativar no boot e iniciar:
 $ sudo systemctl daemon-reload
 $ sudo systemctl enable --now ccdvi.service

 9.4 Validar o servico e a aplicacao:
 $ sudo systemctl status ccdvi.service --no-pager
 $ curl -fsS http://127.0.0.1:5173/api/health
       # esperado: {"status":"ok"}

 9.5 Comandos de operacao:

 Iniciar .............: sudo systemctl start ccdvi.service
 Parar ...............: sudo systemctl stop ccdvi.service
 Reiniciar ...........: sudo systemctl restart ccdvi.service
 Status ..............: sudo systemctl status ccdvi.service --no-pager
 Logs recentes .......: sudo journalctl -u ccdvi.service -n 80 --no-pager
 Logs ao vivo ........: sudo journalctl -u ccdvi.service -f
 Habilitar no boot ...: sudo systemctl enable ccdvi.service
 Desabilitar no boot .: sudo systemctl disable ccdvi.service

 Ao pressionar Ctrl+C durante "journalctl -f", SOMENTE a visualizacao dos
 logs e interrompida: o servico continua rodando. Para encerrar de verdade,
 use "sudo systemctl stop ccdvi.service".

 9.6 Validacao de parada e retorno:
 $ sudo systemctl stop ccdvi.service
 $ sudo systemctl is-active ccdvi.service
       # esperado: inactive
 $ sudo systemctl start ccdvi.service
 $ sudo systemctl is-active ccdvi.service
       # esperado: active
 $ curl -fsS http://127.0.0.1:5173/api/health
       # esperado: {"status":"ok"}

 9.7 Validacao de inicializacao automatica (apos assegurar acesso SSH):
 $ sudo systemctl is-enabled ccdvi.service
       # esperado: enabled

     Opcional, em janela de manutencao: reinicie a VM e confirme o status
     e a API. O PostgreSQL tambem deve iniciar normalmente pelo systemd.


-------------------------------------------------------------------------------
 10. OPERACAO DO DIA A DIA
-------------------------------------------------------------------------------

 Agora utilize SEMPRE o servico systemd da secao 9 (nao execute dev-up.sh
 manualmente enquanto o servico estiver ativo).

 Parar ............: sudo systemctl stop ccdvi.service
 Iniciar ..........: sudo systemctl start ccdvi.service
 Reiniciar ........: sudo systemctl restart ccdvi.service
 Consultar ........: sudo systemctl status ccdvi.service --no-pager
 Acompanhar logs ..: sudo journalctl -u ccdvi.service -f

 O terminal e liberado imediatamente apos start/stop. No journalctl,
 Ctrl+C apenas encerra a exibicao dos logs.

 Onde ficam os dados:
   - Banco ............: PostgreSQL, banco "dvi"
   - Anexos ...........: ~/ccdvi-sistema-offline/backend/var/storage/

 Backup (gera um arquivo .tar com banco + anexos + hashes):
 $ cd ~/ccdvi-sistema-offline
 $ set -a; . backend/.env; set +a
 $ export PGPASSWORD=<SENHA_DO_BANCO>
 $ DVI_STORAGE_DIR=backend/var/storage scripts/backup.sh ~/backups-dvi
       # Para backup criptografado, defina antes DVI_BACKUP_GPG_RECIPIENT
       # (veja docs/INSTALACAO.md, secao 3).

 ATENCAO: BACKUPS contem informacoes sensiveis e devem ser protegidos.

 Atualizar para nova versao do Sistema DVI (janela de manutencao):
 $ sudo systemctl stop ccdvi.service
 $ cd ~/ccdvi-sistema-offline
 $ git status
       # so prossiga se nao houver alteracoes locais importantes
 $ git pull --ff-only
       # Se necessario, refazer dependencias conforme docs/INSTALACAO.md.
       # O dev-up.sh executado pelo servico aplica as migracoes no inicio.
 $ sudo systemctl start ccdvi.service
 $ sudo systemctl status ccdvi.service --no-pager
 $ curl -fsS http://127.0.0.1:5173/api/health

 Caso a atualizacao falhe, analise os logs e nao repita operacoes destrutivas:
 $ sudo journalctl -u ccdvi.service -n 100 --no-pager


-------------------------------------------------------------------------------
 11. SOLUCAO DE PROBLEMAS
-------------------------------------------------------------------------------

 "DVI_DATABASE_URL: Defina DVI_DATABASE_URL em backend/.env"
   -> O arquivo backend/.env nao existe ou a linha esta comentada. Refaca o
      passo 5.

 "connection ... failed: Connection refused" (porta 5432)
   -> PostgreSQL parado.  $ sudo systemctl start postgresql

 "password authentication failed for user dvi"
   -> Senha em backend/.env diferente da criada no passo 3.2. Para redefinir:
      $ sudo -u postgres psql -c "ALTER ROLE dvi PASSWORD '<NOVA_SENHA>';"
      e atualize backend/.env.

 "DVI_SEED_PASSWORD invalida: A senha deve ter pelo menos 10 caracteres."
   -> Ajuste DVI_SEED_PASSWORD no backend/.env (minimo 10 caracteres).

 "Address already in use" (porta 8000 ou 5173)
   -> A porta ja esta em uso. Identifique o processo antes de encerra-lo:
      $ sudo systemctl status ccdvi.service --no-pager
      $ sudo ss -ltnp | grep -E ':(5173|8000)\b'
      Evite pkill generico; nao execute dev-up.sh se o servico ja roda.
      Para reiniciar o servico: sudo systemctl restart ccdvi.service.

 "Permission denied" ao executar scripts/dev-up.sh
   -> $ chmod +x scripts/*.sh
      Depois use sudo systemctl restart ccdvi.service.

 Erros de sintaxe do Vite/npm ou "Unsupported engine"
   -> Node.js antigo. Confira  $ node --version  (precisa ser v22.x).
      Pare o servico antes de reinstalar as dependencias:
      $ sudo systemctl stop ccdvi.service
      $ rm -rf frontend/node_modules
      $ sudo systemctl start ccdvi.service

 Erro ao instalar dependencias Python ("ensurepip" / "venv")
   -> $ sudo apt install -y python3.12-venv
      Pare o servico antes de recriar o ambiente Python:
      $ sudo systemctl stop ccdvi.service
      $ rm -rf backend/.venv
      $ sudo systemctl start ccdvi.service

 Outro computador nao abre a pagina
   -> Use o IP correto (hostname -I), confirme a mesma rede Wi-Fi/LAN e
      libere a porta 5173 no firewall (passo 7.3).

 "Usuario ou senha invalidos" no login
   -> Os usuarios sao criados com a senha que estava em DVI_SEED_PASSWORD
      NA PRIMEIRA execucao. Alterar a variavel depois nao muda senhas ja
      criadas.

 "Muitas tentativas. Aguarde alguns minutos."
   -> Bloqueio de seguranca apos 5 senhas erradas. Aguarde 15 minutos.
      Nao reinicie o sistema para contornar controles de autenticacao.
